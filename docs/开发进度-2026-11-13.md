## 2. 本轮完成

### 上下文分析扩容

- 单条日志 AI 分析与日志页逐条 AI 分析的上下文窗口新增 `±50 / ±100 / ±200`，保留 `±5 / ±10 / ±20`，默认 `±20`。
- 后端单侧上下文上限提高到 500，总量上限 1000；查询引擎 `Context` 同步放宽。
- Prompt 在上下文超过上限时围绕目标日志截取连续窗口，保证目标日志不被截掉；按实际可用预算动态缩短每条上下文行，并把实际写入 Prompt 的条数回填为“已分析 N 条”。
- 提示词中会注明上下文截断范围与“目标日志已保留”。

### 日志聚合维度

- 新增派生字段：
  - `event_type`：优先日志字段 `event_type`，其次 Windows Provider，再回退到日志文件名/来源；
  - `source_ip`：兼容 `source_ip` / `src_ip` / `IpAddress` / `SourceIp` / `RemoteIp` / `ClientIp` 等命名；
  - `destination_ip`：兼容 `destination_ip` / `dest_ip` / `DestinationIp` / `DestAddress` / `TargetIp` 等命名。
- 查询语法支持 `event_type:...`、`source_ip:...`、`destination_ip:...`。
- 日志工作台“聚合图表”新增“维度”选择，可按事件类型、来源 IP、目的 IP、事件 ID、主机、级别查看 Top 10。
- “AI 日志分析 → 聚合分析”新增聚合维度多选（默认事件类型 + 事件 ID），后端按查询范围内全部日志计算各维度 Top 20，随采样日志一起提交 AI，并在结果中展示“聚合统计”。

### 分析报告范围

- 生成分析报告新增独立范围选择：
  - 时间范围：沿用当前查询 / 15m / 1h / 24h / 7d / 全部 / 自定义；
  - 日志类型（项目日志源）；
  - 来源 IP、目的 IP、事件 ID；
  - 聚合维度多选。
- 报告日志条数改为“采样上限”，仅限制提交给 AI 的样本数；统计范围由时间/类型/IP/事件 ID 决定。
- 报告结果新增“分析范围聚合”，展示各维度总量与 Top 项。
- 范围输入留空时沿用当前查询中的同名条件；显式填写才覆盖。

### 调查工单完善

- 新增“关联日志”面板：后端优先返回证据日志，其次按线索值检索（最多 200 条）；可打开日志详情，也可把线索命中日志一键标记为证据。
- 证据链支持按 DocID 直接添加证据与备注；日志页/日志详情的原有标记方式保留。
- 调查时间线与 AI 研判时间线中的 DocID 改为可点击，直接打开日志详情抽屉。
- 编辑工单支持修改线索类型/线索值、时间范围、状态、风险分、处理人与标签；支持清空时间范围与风险分。
- 支持删除工单（确认后删除证据标记与 AI 研判，不删除原始日志）。
- 工单列表自动选中未结案工单，搜索支持描述；日志条目线索类型不再显示原始 `log_entry`。
- 证据包升级为 1.1：新增 `logs.jsonl`（关联日志 JSONL）与 `README.txt`，并纳入 manifest SHA256；导出内容与文档描述一致。
- 后端修复线索检索：`event_id` 线索按结构化事件 ID 检索，`log_entry` 仅使用证据；不再用零值时间范围过滤掉日志。

### 兼容与持久化

- AI 分析结果新增 `aggregates` 字段；本地历史记录缺少该字段时按无聚合结果恢复，不报错。
- `LogAnalysisRequest`/`AnomalyDetectionRequest`/`ReportRequest` 模型与前端 TypeScript 契约同步扩展。
- `InvestigationUpdates` 新增线索、时间范围与清空标记字段；旧工单数据可直接打开与编辑。
