## 2. 产品需求分析

### 2.1 用户与场景

- **用户**：个人安全分析师、运维工程师、应急响应人员；单机单用户，无账号体系。
- **场景**：事件排障、入侵调查、日志取证、威胁狩猎。
- **价值主张**：日志不出本地；一个可执行文件完成采集→解析→检索→分析→取证；AI 可选。

### 2.2 功能地图与优先级

**P0（核心闭环，必须完整可用）**
1. 项目隔离管理（创建/打开/归档/删除/导入导出、统计）。
2. 本地日志采集（文件/通配符/递归/gzip；Windows evtx；Linux journalctl/文本日志）。
3. 解析（内置模板、正则、JSON、syslog、多行；格式检测；预览解析）。
4. 存储与索引（LZ4 压缩日志、倒排/时间/bitmap 索引、持久化）。
5. 查询（关键词 AND/OR/NOT、字段过滤、时间范围、分页排序、上下文、聚合、模式聚类）。
6. 前端主工作台（项目页、日志查看页、虚拟滚动、筛选、图表、详情/上下文）。
7. 设置（通用、AI、SSH、模板、规则）。

**P1（应急响应闭环，完整可用）**
8. SSH 远程采集（密钥/密码、gzip 拉取、journalctl、增量、并发、命令白名单）。
9. AI 辅助（多提供商、连通性测试、AI 生成解析模板、异常检测、根因分析、自然语言查询、报告）。
10. 调查工单（线索、证据标记、时间线、AI 分析、证据导出）。
11. 威胁狩猎（IOC 导入/检索、YAML 规则引擎、内置规则、检测结果、取证包）。

**P2（骨架/后续增强）**
12. 实时文件监控（fsnotify）——实现采集器能力，UI 暂不暴露持续监控开关。
13. Bloom 过滤器——按设计构建并持久化，作为查询快速否定与统计能力。
14. 项目离线包校验（SHA256 manifest）。
15. 性能基准与大规模（5000 万条）压测——提供基准测试脚本，不在本机跑满规模。

### 2.3 核心用户流程

```
创建项目 → 采集(本地/SSH/evtx) → 选择解析模式(内置模板/AI生成) → 预览 → 确认导入
   → 构建索引 → 日志工作台(搜索/筛选/图表/聚类) → 标记证据/建调查工单
   → AI 分析(异常/根因/时间线) → 威胁狩猎(IOC/规则) → 导出报告/取证包
```

### 2.4 非功能指标与可行性

| 指标 | 文档要求 | 落地策略 |
|---|---|---|
| 导入速度 ≥100MB/s | 高 | 流式读取 + 批量 LZ4；受磁盘/CPU限制，提供并发参数 |
| 全文搜索 <100ms（千万级） | 高 | 内存倒排 + roaring bitmap 交集；MVP 验证百万级 |
| 复杂查询 <500ms | 中 | bitmap 优先、时间裁剪、结果分页 |
| 内存峰值 <2GB | 中 | 索引内存占用随数据线性增长；MVP 以千万级为目标，预留分片扩展点 |
| 冷启动 <3s | 中 | 元数据启动、索引按项目惰性加载 |
| 单可执行文件 | 高 | Wails 嵌入前端；内置模板/规则 go:embed |

> 说明：5000 万条日志下“全内存倒排 + <2GB”在 Go 中很难同时满足。实现将索引驻留内存并记录内存预算；超大规模通过后续分片索引扩展，不作为本次验收阻塞项。

## 3. 技术架构分析

### 3.1 架构落地

- **桌面应用**：Wails v2，Go 后端 + WebView2 前端；无 HTTP 服务。
- **分层**：`pkg/models`（模型/DTO）→ `internal/*`（领域包）→ `internal/app`（服务编排 + Wails 绑定）→ `frontend`（SolidJS）。
- **数据流**：
  ```
  采集器(RawLine) → 解析器(LogEntry) → 索引构建器(LogStore + 4 类索引)
  查询请求 → 语法解析 → bitmap/倒排/时间裁剪 → 文档读取 → 分页结果
  ```
- **长任务**：采集/解析/索引、AI 分析、规则检测为异步任务，通过 Wails Events 推送进度；API 返回 taskID。
- **持久化**：
  - 全局：`data/metadata.db`（SQLite WAL）。
  - 项目：`data/projects/<id>/{project.meta, raw/, indexes/}`。
  - 配置/模板/规则：内置资源嵌入，首次运行播种到 SQLite/数据目录，用户可覆盖。

### 3.2 文档设计问题与修正（关键）

1. **Hyperscan 不可用**：`github.com/intel/hyperscan-go` 需要 C 库与本地构建，Windows 分发困难，与“单文件零依赖”冲突。
   **修正**：使用 Go 标准库 `regexp`（RE2 语义）+ 自定义分词器；多模板匹配用预编译正则 + 格式检测；保留接口以便未来可选接入 Hyperscan。
2. **索引文件设计不自洽**：文档让查询执行器通过 `timeIndex.GetOffset(docID)` 取日志 offset，但时间索引是 B+ 树，且未定义 docID→日志 offset 的映射。
   **修正**：新增独立 `docs.idx`（docID → 压缩块偏移/长度）；时间索引只存排序后的 (timestamp, docID)。
3. **UUID 作为每条日志 ID**：36 字节 × 5000 万 ≈ 1.8GB 仅 ID。
   **修正**：内部使用 `DocID uint64` 紧密编号；对外 `ID = strconv.FormatUint(docID,10)`。
4. **索引并发写未定义**：文档 worker 并发 `AddEntry` 直接写共享 Posting List，`processBatch` 顺序处理却又用多 worker 批量，二者矛盾。
   **修正**：构建阶段单写者（或分片 worker + 合并）；索引写入由构建器串行化，采集/解析并行。
5. **同步 API 无法反馈进度**：`CollectSSH` 等长任务同步返回，UI 无进度。
   **修正**：`Start*Collection` 返回 `TaskInfo`，事件 `collect:progress` / `collect:done`；保留 `StopCollection`。
6. **SSH 命令拼接注入风险**：文档直接 `fmt.Sprintf("grep -E '%s' ...")`。
   **修正**：严格 shell quote；命令白名单只用于固定命令模板；路径与正则参数逐项转义；禁止任意脚本。
7. **凭据加密密钥管理缺失**：文档只说 AES-256。
   **修正**：首次运行生成 `data/secrets.key`（32B，0600），AES-256-GCM 加密 SSH 密码/AI Key；密钥文件与数据同目录（便携），文档注明风险与备份要求。
8. **evtx 库 API 需适配**：`0xrawsec/golang-evtx` 的解析入口与文档伪代码不同。
   **修正**：以库实际 API 封装，标准化为 JSON 记录（timestamp/level/event_id/provider/computer/user_id/message/fields）。
9. **journalctl 仅 Linux**：Windows 构建必须可编译。
   **修正**：代码跨平台编译，运行时校验 OS 并返回明确错误。
10. **AI 输出不可直接信任**：正则/JSON 可能非法。
    **修正**：Prompt 强制 JSON、提取首个 JSON 块、校验与重试一次；所有 AI 功能在未配置时返回明确错误，不影响核心功能。
11. **ZIP 导出/导入安全**：导入项目包/证据包需防 Zip Slip、符号链接、超大文件。
    **修正**：校验 entry 路径在目标目录内、限制单文件/总大小、拒绝非常规文件。
12. **时区**：日志时间多样。
    **修正**：解析时尽量带时区；无时区按本地时区解释，存储统一 UTC，前端本地化展示。
13. **规则 DSL 不完整**：`filter`/`condition` 只是示例。
    **修正**：定义字段+操作符+窗口聚合的 YAML DSL（见 §5.6），实现阈值/分组/时间窗。
14. **前端依赖**：`@tanstack/solid-virtual` 实际包名为 `@tanstack/solid-virtual`（v3），与文档示例一致；Tailwind 固定 3.4。
15. **Wails 脚手架**：Wails v2 CLI 无 Solid 模板时手工搭建 `frontend/`（Vite + Solid），`wails.json` 指定 build 命令。
16. **程序目录写入权限**：安装在 `Program Files` 时无法写数据。
    **修正**：默认便携数据目录 = 可执行文件旁 `data/`；启动时检测不可写则回退到用户目录 `%APPDATA%/GLog`，并在系统信息中展示实际路径。
17. **文档“继续”痕迹与重复章节**：实现以合并后的完整设计为准。

```
│   ├── indexer/                        # 索引 agent（日志存储+索引）

```

### 5.2 日志存储与索引格式（修正版）

- `raw/logs.dat`：`GLOGSEG1` 文件头；每条日志一个块：
  `[compressedLen uint32][uncompressedLen uint32][lz4(JSON(LogEntry))]`。
- `indexes/docs.idx`：`GLOGDOC1` + count + N × `{offset uint64, storedLen uint32, rawLen uint32}`。
- `indexes/inverted.idx`：`GLOGINV1` + docCount + termCount + 词典（term、posting offset/len、df）+ postings（delta+uvarint docID）。
- `indexes/time.idx`：`GLOGTIM1` + count + 按时间排序的 `{ts int64 ns, docID uint32}`。
- `indexes/bitmap.idx`：`GLOGBMP1` + field/value 元数据 + roaring 序列化数据。
- `indexes/bloom.idx`：`GLOGBLM1` + 按小时桶的布隆过滤器。
- `indexes/meta.json`：统计、源区间（sourceID → docID 范围）、构建时间、版本。
- 追加语义：每次采集追加日志并增量更新内存索引，任务结束后原子重写索引文件（临时文件 + rename）。
- 文档 docID 从 0 连续分配；索引重建可从 `raw/logs.dat` 全量重放。

### 5.3 解析契约

- 输入：`models.RawLine{Text, FilePath, Offset, Size, SourceID, SourceHost, Seq}`。
- 输出：`models.LogEntry`，必填 Timestamp（无则采集时间）、Level（无法判断为 UNKNOWN）、Message、RawLog、Fields。
- 模板：正则（Go RE2）、JSON、Syslog 内置解析器；多行在解析前按模板配置合并。
- 模板 YAML 字段与 `models.ParseTemplate` 对齐；支持 `field_map`、`time_format`、`level_map`、`level_extraction`、`multiline`、`examples`。
- 格式检测返回 `{detected_format, confidence, suggested_templates}`。

### 5.4 查询语法（落地子集）

```
keyword                          # 分词后 AND
"exact phrase"                   # 子串短语
error AND timeout
error OR timeout
NOT debug
level:ERROR
host:web-01
source:src_001
event_id:4625
fields.status:[400 TO 499]
@timestamp:[2024-01-01T00:00:00Z TO 2024-01-02T00:00:00Z]
(level:ERROR OR level:CRITICAL) AND host:web-01
```

- 隐含 AND；大小写不敏感；`*` 仅支持后缀通配（转前缀扫描）。
- 字段过滤映射：level→bitmap、host/source/event_id→bitmap、timestamp→time idx、其他→匹配后逐条过滤。

### 5.5 异步任务事件

- `collect:progress` → `{task_id, progress, message, processed, total}`
- `collect:done` → `{task_id, status, error, result}`
- `analysis:progress`（AI/规则）→ 同上结构。

### 5.6 检测规则 DSL（落地）

```yaml
name: SSH暴力破解
severity: high
enabled: true
detection:
  filter:
    - field: level          # 内建字段 level/source_host/source/message/event_id/fields.x
      op: one_of            # eq/ne/contains/prefix/regex/one_of/gt/lt/gte/lte
      value: ["WARN", "ERROR"]
    - field: message
      op: contains
      value: ["Failed password", "authentication failure"]
      match: any            # all/any（默认 any）
  group_by: ["fields.remote_addr"]
  condition: count > 10 within 5m   # 支持 count >/>=/</<= N within Nm/Nh
actions:
  tags: [brute_force]
  risk_score: 85
  alert:
    title: ...
    message: ...
```

### 7.2 实施期新增/修正

1. **Windows EVTX 非管理员采集**：直接读取 `winevt\Logs\*.evtx` 被系统拒绝时，自动调用 `wevtutil epl` 导出到临时目录后解析，任务结束后清理；Security 通道仍需管理员。
2. **独立日志详情页**：日志列表悬停行可进入独立的“日志详情”页面，提供解析 JSON / 原始日志 / 字段表三个不截断视图、复制、上一条/下一条、返回列表（保留原查询与滚动位置）、元数据与相邻日志，满足完整读取/解析内容核查需求。
3. **虚拟滚动 WebView2 兼容**：TanStack Virtual 初次挂载可能拿不到 targetWindow，导致 scrollRect 为 0；增加观察器重新绑定逻辑并固定 `@tanstack/solid-virtual@3.10.8`。
4. **威胁检测上限**：查询引擎单次上限提高到 200,000 以匹配规则检测候选，UI 层仍限制 1000。
5. **第三方 EVTX 库日志**：接管其标准日志输出并降级为 debug，避免 stderr 堆栈干扰；不持有文件句柄，保证测试与退出清理。
6. **启动便利性**：仅有一个活跃项目时自动打开并进入日志工作台；启动时自动扫描本机日志来源。
7. **测试覆盖**：新增解析、索引/查询、AI、存储/加密、项目、采集器、威胁规则及 App 端到端测试（见 README）。
8. **只读演示/验证工具**：`cmd/seeddemo`、`cmd/hostlogtest`、`cmd/evtxtest`，便于复现主机日志与真实 EVTX 验证。
9. **本机日志自动发现**：扫描 Windows 事件通道、`C:\Windows\Logs`（CBS/DISM/setupapi）、IIS/Nginx/Apache/数据库路径、ProgramData 与用户目录；样本匹配模板，按类别优先级与目录上限筛选。项目总览仅显示数量摘要，数据采集页展示完整列表并可一键填入路径/模板。
10. **本机数据可复用为日志源**：本地采集/导入完成后自动登记项目日志源；日志源详情支持“再次采集”，EVTX 使用原生解析；本地采集显式 EVTX 路径自动切换原生 EVTX 解析，受保护通道给出引导。
11. **界面重构**：统一浅色工作台设计（中性背景、白色面板、蓝色强调、IBM Plex 字体），修复侧栏网格/长路径导致的横向溢出；图表与表格同步浅色主题。
12. **AI 服务配置增强**：支持从 OpenAI 兼容 `/models` 识别模型、勾选模型并在保存前测试模型连通性。
13. **单条日志 AI 分析**：日志详情支持“仅分析本条”或结合 ±5/±10/±20 条上下文分析；结果含风险、发现、建议与相关 DocID。
14. **日志列表增强**：列表直接显示事件 ID；EVTX 原始消息转换为中文字段摘要；双击展开全部识别字段，字段名中文显示并保留原始键。
15. **威胁狩猎重构**：移除内置规则与 IOC 界面，检测统一由 AI 完成；检测结果按项目持久化，重新打开不自动重跑；新增“网络连接”面板查看监听端口、外联连接、外部 IP，支持 5 秒实时刷新。
16. **推理模型兼容**：默认 `max_tokens` 提升到 8192，避免 deepseek-flash 等推理模型在生成正文前耗尽 token 导致空内容。
